# PBB16 ISA 规格说明

> 整理自 `00.txt`（@GES233 2017，2021 修订），作为软核译码器的设计输入。
> 带 ✅ 的条目已经过 `20171002_CPU.circ` XML 静态分析（组件属性 + 导线追踪）
> 确认；带 ⚠ 的条目为存疑/未实现项。**电路与文档冲突时，以电路为准。**
> 注意：电路是 Logisim 门级实现，解码器为**纯组合逻辑（无微码 ROM）**。

- 字长：16 位定长指令
- 指令条数：60
- 通用寄存器：R0–R7（16 位，R6 栈指针仅 12 位）
- 控制寄存器：CR0–CR15（见下文寄存器章节）
- 内存按字节编址，**仅支持 16 位字访问，地址必须偶数对齐**（见 2.6）

---

## 1. 指令格式

opcode 共 5 位，由 op1（bit 15:13）+ op2（bit 12:11）组成。
✅ 解码器用一个 5→32 Decoder 按 opcode 分出各格式类，与下表对应关系已逐条核对。

```
 bit  15 14 13  12 11  10 09 08 07 06 05 04 03 02 01 00
     ┌──────────┬──────┬────────────────────────────────┐
 I   │   op1    │ op2  │  x  x  x  x  x  x  x  x  x  x  x │  无操作数
 II  │   op1    │ op2  │           Immediate[10:0]        │  11 位立即数
 III │   op1    │ op2  │  o  o │     Immediate[8:0]       │  9 位立即数
III-I│   op1    │ op2  │ [rgs] │     Immediate[7:0]       │  寄存器 + 8 位立即数
III-II│  op1    │ op2  │ [fct] │     Immediate[7:0]       │  3位fct + 8 位立即数
 IV  │   op1    │ op2  │  o  o  o  o  o │     [fct]       │  ⚠ 保留，未使用
IV-I │   op1    │ op2  │[rgs_1]│[rgs_2]│      [fct]       │  双寄存器 + 5位fct
IV-II│   op1    │ op2  │  x │   [rgs]   │      [fct]      │  控制寄存器传送
IV-A │   op1    │ op2  │ [r1][r2][r3][flg]│    [fct]      │  三寄存器算术 + 标志
IV-L │   op1    │ op2  │ [r1][r2][r3]│        [fct]       │  三寄存器逻辑
IV-S │   op1    │ op2  │ [r1][r2]│  [s]  │     [fct]      │  移位（shamt）
 V   │   op1    │ op2  │ [fct] │ [rgs] │  o  o  o  o  o   │  栈操作
 VI  │   op1    │ op2  │  o  o  o  o  o │  Immediate[5:0] │  6 位立即数
VI-I │   op1    │ op2  │ [1] x │ [fct] │  Immediate[5:0]  │  跳转/调用
VI-II│   op1    │ op2  │ [rgs] │ [fct] │  Immediate[4:0]  │  ⚠ 保留，未使用
VI-III│  op1    │ op2  │ [r1][2][i][f]│  Immediate[5:0]  │  访存 LOD/STR
VI-IV│   op1    │ op2  │ [flg][cm][fct]│  Immediate[5:0] │  条件跳转
 VII │   op1    │ op2  │  o  o  o  o  o  o  o  o  o  o  o │  保留
```

### 字段含义

| 字段 | 位宽 | 含义 |
|---|---|---|
| `op1`/`op2` | 3+2 | 主操作码 |
| `[fct]`/`[f]` | 1/2/3/5 | 功能码（区分同 opcode 下的具体操作）✅ 解码器按格式零扩展成 6 位功能码总线 |
| `[rgs]` | 3 或 5 | 通用寄存器编号（R0–R7）✅ |
| `[rgs_1]`/`[rgs_2]` | 3+3 | 双通用寄存器编号 ✅ |
| `[r1]`/`[r2]`/`[r3]` | 2 | 寄存器选择 ✅ 高位补 0 扩展成 3 位地址 → **只能选 R0–R3** |
| `[2]` | 1 | 地址寄存器选择 ✅ 0=A0(R4)，1=A1(R5) |
| `[1]` | 1 | AR 选择 ✅ 程序计数器内按 bit0 在 AR0/AR1（即 A0/A1）间选 |
| `[flg]` | 2 | ALU 标志选择：`11:Z 10:V 01:S 00:C` ✅ 条件成立判定 = flag XNOR [cm] |
| `[cm]` | 1 | 比较值（条件跳转中期望的标志值）✅ |
| `[i]` | 1 | 中断使能 ⚠ **电路中未接线**，无消费者 |
| `[s]` | 4 | shamt，移位位数 ✅ 解码器直接输出 4 位移位位数总线 |
| `Immediate` | 5/6/8/9/11 | 立即数，扩展规则见 2.11 |
| `x` | — | 无用位 |
| `o` | — | 其他/保留位 |

✅ **寄存器寻址总规则**：数据通路中寄存器地址一律 3 位（R0–R7 = D0,D1,D2,D3,A0,A1,SP,CBR）。
2 位/1 位字段在解码器里补 0 扩展，因此：
- IV-A / IV-L / IV-S / VI-III 的 `[rN]`（2 位）只能访问 **R0–R3**；
- R4–R7 只能靠本身就是 3 位的 `[rgs]` 字段（MOVI/MOV/MOVUI/XCHG、栈操作）寻址；
- SP(R6) 物理上在 `堆栈` 子电路内，**不能经通用写口写入**；CBR(R7) 只能经写口 2 写入（写口 1 的地址 7 输出悬空——疑似原电路 bug，软核实现时可自行修正）。

## 2. 指令编码总表

### 2.1 空操作 / 数据传送

| 助记符 | 格式 | opcode | fct | 语义 |
|---|---|---|---|---|
| NOP   | I     | `000 00` | — | 无操作 ✅ |
| MOVI  | III-I | `001 00` | — | R[rgs] = Imm8（**零扩展**，样例 `20 ff` → R0=0x00FF）✅ |
| MOVUI | III-I | `001 01` | — | R[rgs] 高位置数 ✅（"U"=upper，字节拼装器实现高字节置数） |
| MOV   | IV-I  | `001 10` | — | 寄存器间传送 ✅ |
| XCHG  | IV-I  | `001 11` | — | 寄存器交换 ✅ |

### 2.2 算术运算（IV-A，opcode `010 00`，fct 3 位）

| 助记符 | fct | 语义 |
|---|---|---|
| ADD  | `000` | 加法 ✅ |
| SUB  | `001` | 减法 ✅ |
| ADC  | `010` | 带进位加 ✅（加法器进位输入直连 ALU `进位` 引脚） |
| SBB  | `011` | 带借位减 ✅ |
| MUXL | `100` | **乘法低 16 位** ✅（ALU 内有 16 位 Multiplier，"MUX"即 MUL） |
| MUXH | `101` | **乘法高 16 位** ✅（Multiplier 进位输出） |
| DIVQ | `110` | 除法商 ✅（16 位 Divider） |
| DIVR | `111` | 除法余数 ✅ |

样例程序中 `R1 = R1 + R2` 编码为 `43 20`：r1=R1、r2=R2、r3=R0、flg=`10`、fct=`000`。
由此推断目的寄存器是 r1。

### 2.3 逻辑运算（IV-L，opcode `010 01`，fct 5 位）

| 助记符 | fct | 语义 |
|---|---|---|
| AND  | `00000` | 与 |
| OR   | `00001` | 或 |
| NOT  | `00010` | 非（`R3 <= ~(R1)`） |
| NAND | `00011` | 与非 |
| NOR  | `00100` | 或非 |
| XOR  | `00101` | 异或 |
| CMP  | `00110` | 有符号比较：R1==R2 → ZF=1；R1>R2(有符号) → SF=1 |
| CMPU | `00111` | 无符号比较：同上，按无符号判断 |

### 2.4 移位（IV-S，opcode `010 10`）✅ 已按电路修正

选择信号 = 功能码低 3 位。ALU 内 7 个 Shifter 的 Mux 连线给出真实编码：

| fct | 电路实际行为 | 助记符 |
|---|---|---|
| `000` | 逻辑左移 | SHL |
| `001` | 逻辑右移 | SHR |
| `010` | 算术右移 | SAR |
| `011` | 循环左移 | SCL |
| `100` | 循环右移 | SCR |
| `101` | 逻辑左移（第二通道，经额外整形逻辑，疑为 SAL） | SAL ⚠ |
| `110` | 逻辑右移（第二通道，经额外整形逻辑） | ⚠ 用途未定 |
| `111` | 浮空未用 | — |

⚠ 原文档把 SHL 列在 000/010、SAR 列在 011/111、SAL 列在 110，与电路不符，
系文档错位/笔误，**上表以电路为准**。101/110 两通道旁有 AND/OR/NOT 门和 16 输入
NOR（Z 标志生成），整形细节未完全确定，建议仿真确认。

### 2.5 立即数逻辑（III-II，opcode `010 11`，fct 3 位）

| 助记符 | fct | 语义 |
|---|---|---|
| ANDI | `000` | 立即数与（with R0） |
| ORI  | `001` | 立即数或（with R0） |
| NOTI | `010` | 立即数非（with R0） |

### 2.6 访存（VI-III，opcode `011 00`）✅ 已按电路确认

| 助记符 | [f] | 语义 |
|---|---|---|
| LOD | `1` | `R[r1] ← MEM[(A0\|A1) + sext(Imm6)]`（r1 只能选 R0–R3） |
| STR | `0` | `MEM[(A0\|A1) + sext(Imm6)] ← R[r1]` |

- 地址 = 地址寄存器（`[2]`：0→A0/R4，1→A1/R5）+ Imm6 **符号扩展** ✅
- `[r1]` 选 D0–D3 作 STR 数据源 / LOD 目的 ✅
- **仅 16 位字访问**：地址 bit0=1（奇地址）触发"地址未对齐异常"并封锁写使能 ✅
- `[i]`（中断使能位）⚠ 电路中找不到消费它的逻辑，**未实现**

### 2.7 栈操作（V，opcode `011 01`，fct 3 位）

| 助记符 | fct | 语义 |
|---|---|---|
| PUSH  | `000` | 压栈 |
| POP   | `001` | 弹栈 |
| SPINC | `010` | SP 自增 |
| SPDEC | `011` | SP 自减 |

栈指针为 R6（12 位），栈物理上是 `堆栈` 子电路内一块 12 位地址 × 16 位 RAM。
✅ 栈生长方向由 Status.SPG（bit13）配置；栈溢出触发异常（EXCode 之一）。

### 2.8 控制寄存器传送（IV-II，opcode `011 10`）⚠ 半成品，勿照抄原文档

电路静态分析结论：

- **唯一接通的 CR 通路是写**：CBR(R7) → Status(CR8) 的 bit14/13/12-9
  （写使能 = `cregsel == 8` 且未被中断打断）✅
- CR 读值（`cregsel` 5 位选择 CR0/8/9/11/15 的 Mux）虽送到数据传送控制中心，
  但内部引脚悬空——**CR → GPR 传送未实现** ⚠
- fct bit0 = 1（MGCU/MGCH）在 GPR 侧效果等同 MOV（R[读地址1] ← R[读地址2]）
- fct = 00（MCGU）且 `模式(EM)=1` 时，行为与 ERET 相同：PC ← EPC
- U/H 后缀在 CR 传送语境下无法从电路确定 ⚠

### 2.9 跳转 / 调用

| 助记符 | 格式 | opcode | fct | 语义 |
|---|---|---|---|---|
| J    | II     | `011 11` | —     | `PC = PC[15:11]:Immed[10:0]` ⚠ 电路中疑似未按此实现（见下） |
| J    | III-II | `100 00` | `000` | `PC = PC[15:8]:Immed[7:0]` ✅ |
| J    | III-II | `100 00` | `001` | `PC = PC + sext(Immed)` ✅ |
| Jx   | VI-IV  | `100 01` | `00`  | `PC = PC[15:6]:AR[5:0]`，仅当 flag[flg] XNOR [cm] ✅ |
| Jx   | VI-IV  | `100 01` | `01`  | `PC = PC + AR`，仅当 flag[flg] XNOR [cm] ✅ |
| Jx   | VI-IV  | `100 01` | `10`  | `PC = PC[15:6]:Immed[5:0]`，仅当 flag[flg] XNOR [cm] ✅ |
| Jx   | VI-IV  | `100 01` | `11`  | `PC = PC + sext(Immed)`，仅当 flag[flg] XNOR [cm] ✅ |
| J    | VI-I   | `100 10` | `000` | `PC = PC[15:6]:AR[5:0]` ✅ |
| J    | VI-I   | `100 10` | `001` | `PC = PC + AR` ✅ |
| CALL | VI-I   | `100 10` | `010` | `PC = PC[15:6]:Immed[5:0]; AR = PC` ✅ |
| CALL | VI-I   | `100 10` | `011` | `PC = PC + sext(Immed); AR = PC` ✅ |
| CALL | VI-I   | `100 10` | `100` | `PC = PC[15:6]:AR[5:0]; AR = PC` ✅ |
| CALL | VI-I   | `100 10` | `101` | `PC = PC + AR; AR = PC` ✅ |
| MAP  | VI-I   | `100 10` | `110` | `AR = PC + sext(Immed)` ✅ |
| RET  | VI-I   | `100 10` | `111` | `PC = AR + 2` ✅（指令占 2 字节） |

注：AR 为地址/返回地址寄存器（A0/A1 之一，由 `[1]` 位选择）。
✅ 相对跳转 `PC + sext(Immed)` 为补码加法，**支持向后跳转**。
⚠ 异常项：电路中第 7 路跳转缓冲的输入是**完整 16 位 immed**（未拼装），
找不到 ISA 所述 `{PC[15:11], Immed[10:0]}` 拼装器——`011 11` 直接跳转的
实现与文档不符，疑似未完成，建议仿真确认。

## 3. 寄存器

### 3.1 通用寄存器（16 位，R6 为 12 位）✅

| 编号 | 电路名 | 用途 |
|---|---|---|
| R0–R3 | D0–D3 | 数据寄存器（算术/逻辑/移位/访存的唯一可选源） |
| R4–R5 | A0–A1 | 地址寄存器（兼作跳转的 AR） |
| R6 | SP | 栈指针（12 位，物理上在堆栈子电路，不可经通用写口写入） |
| R7 | CBR | 与控制寄存器交互（只能经写口 2 写入） |

### 3.2 控制寄存器（16 位）✅ 按电路 CR 读 Mux 确认

| 编号 | 名称 | 访问 | 说明 |
|---|---|---|---|
| CR0 | zero | R | 恒零 ✅ |
| CR1–CR7 | — | — | Mux 输入浮空，实际未接 ⚠ |
| CR8 | Status | 读：全字段；写：仅 bit14/13/12-9（经 CBR） | 见 3.3 |
| CR9 | Cause | R | `IP[6:3]` 中断请求（4 位，来自中断 #0–3 引脚），`excode[2:0]` 异常码 ✅ |
| CR10 | — | — | 未接 |
| CR11 | EPC | R | 异常触发时 EPC ← PC ✅ |
| CR12–CR14 | — | — | 未接 |
| CR15 | Processor ID | R | 电路中接常量 `0x0401`（type/version 布局与文档吻合）✅ |

### 3.3 Status 寄存器（CR8）位定义 ✅ 按电路修正

```
 bit  15    14    13    12..9   8   7..4   3     2     1    0
    ┌─────┬─────┬─────┬───────┬───┬──────┬─────┬─────┬────┬────┐
    │ en  │ BLE │ SPG │ (IM写)│Res│  IM  │ ERL │ EXL │ IE │ EM │
    └─────┴─────┴─────┴───────┴───┴──────┴─────┴─────┴────┴────┘
```

| 位 | 名称 | 电路实情 |
|---|---|---|
| 15 | en | **硬连线恒 0**（无实体寄存器）⚠ |
| 14 | BLE | 真实寄存器（大小端选择），软件可写 ✅ |
| 13 | SPG | 真实寄存器（栈生长方向），软件可写 ✅ |
| 12:9 | — | **写侧**：软件写 Status 时 IM 实际写入 bits12:9 ⚠ 读写不对称 |
| 8 | Reserve | — |
| 7:4 | IM | **读侧**：中断屏蔽（4 位）✅ |
| 3 | ERL | **硬连线恒 0** ⚠ |
| 2 | EXL | 真实寄存器（异常有效）✅ |
| 1 | IE | 真实寄存器（中断级）✅ |
| 0 | EM | 真实寄存器（模式）✅ |

即：软件（经 CBR→Status 通路）只能写 bit14/13/12-9；en、ERL 恒读 0。
⚠ 文档原文把 IM/SPG 位置写作 bit7:4 / bit8，与电路（读侧 7:4、写侧 12:9、SPG 13）不一致，以电路为准。

### 3.4 异常流程 ✅（控制器）

1. 触发源：TRAP 指令、地址未对齐、栈溢出、外部中断 #0–3（经 IM 屏蔽后）。
2. 触发时：EPC ← PC；EXCode ← 优先级编码（1–6）；PC ← 向量表。
3. 向量表（按 EXCode 索引）：code0=0x0000；code3=0xFE80；code1/2/4/5/6=0xFF00；code7=0x0000。
4. ERET（或 011 10/fct=00）在 EM=1 时 PC ← EPC。
   ⚠ EXCode 与触发源的完整对应表未从 XML 全部追完，实现时可自行定义。

## 4. 样例程序（原文附带，计数循环）

```
 地址(字节)     机器码      汇编
0000_0000:     20 ff       R0 = FF
0000_0002:     22 01       R2 = 1
0000_0004:     43 20       loop: R1 = R1 + R2
0000_0006:     48 87       CMP R1, R0
0000_0008:     8e a4       JP[jump] if flag[Z] = 0
0000_000a:     ff ff       HLT
0000_000c:     78 04       jump: JP[loop]
```

⚠ 手工汇编核对结果：`20 ff`/`22 01`/`43 20`/`78 04`/`ff ff` 与格式定义完全吻合；
`48 87` 低 5 位为 `00111`（CMPU）而注释写的是 CMP，`8e a4` 的 Imm6 与目标地址
也有出入——疑为当年手工汇编笔误，实现译码器时以格式定义为准，不要照抄这两条。

## 5. 软核实现备忘（电路分析后的剩余待办）

已确认、可直接照做：寄存器 3 位寻址与补 0 扩展、乘除法器、移位编码（以 2.4 为准）、
LOD/STR 地址计算与对齐检查、立即数扩展规则（2.11）、条件跳转判定（flag XNOR cm）、
异常流程框架（3.4）、CR8/9/11/15 的定义。

仍需决策/验证的开放项（实现时自行定夺或仿真确认）：

1. `[i]` 位（VI-III 中断使能）：电路未接，**建议在软核中直接忽略或定义为保留位**。
2. `011 11` 直接跳转：电路疑似未完成，建议按 ISA 文档实现 `PC[15:11]:Immed[10:0]`。
3. 移位 fct=101/110 通道的整形逻辑（SAL 语义）未完全确定。
4. MCGU/MGCU/MCGH/MGCH 为半成品，**建议在软核中重新设计**（参考 2.8 的电路现状）。
5. Status 写侧 IM 在 bits12:9、读侧在 bits7:4 的不对称：疑似 bug，建议软核统一为 bits7:4。

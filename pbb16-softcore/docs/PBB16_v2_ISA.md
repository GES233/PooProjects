# PBB16 v3 ISA 规格说明（草案）

> PBB16 的中度重设计版，作为 Verilog 软核的设计输入。
> 原始版规格见 `../../PBB 16/PBB16_ISA.md`。
> **本文档是草案，待 @GES233 审阅；标注 ❓ 的条目是设计决策点，欢迎推翻。**
>
> v3 = v2 + 4MB 物理寻址扩展（破坏性变更，无下游包袱）：
> 新增 4 条远访存指令（FLOD.W/FSTR.W/FLOD.B/FSTR.B，寄存器对拼 22 位物理地址，
> 见 3.6b）与内存 banking（CR4–CR7 + Status.MAPE，见第 8 节），
> 指令数 48 → 52，PRID 0x0402 → 0x0403。

设计原则：

- 保留 PBB16 的精神：16 位定长指令、8 个 16 位通用寄存器、
  op1(3 位) + op2(2 位) 的 5 位主操作码结构
- 修复原版硬伤：ALU 放开到 R0–R7、栈并入主数据内存、砍掉未实现的半成品
- 面向仿真（iverilog）先跑通，代码按可综合风格写但不做时序承诺
- 宁缺毋滥：每条指令都要有明确的硬件对应，不要原样照搬画饼

---

## 1. 总览

| 项目 | 规格 |
|---|---|
| 指令字长 | 16 位定长，按 2 字节对齐 |
| 数据字长 | 16 位 |
| 内存 | 字节编址，**小端**（原版 BLE 可配大小端，v2 固定） |
| 通用寄存器 | R0–R7，全部 16 位、全部可参与任何运算 |
| 栈 | 在主数据内存中，**约定 R6 = SP**，向下生长（PUSH 先减后写） |
| PC | 16 位，字节地址；复位后 PC = 0x0000，R6 由软件初始化 ❓ |
| 标志 | Z / S / C / V（内部标志寄存器，不占控制寄存器编号） |
| 指令条数 | 52 |
| 物理地址 | 22 位（4MB），v3 起经 banking / 远访存到达（第 8 节、3.6b） |

ABI 约定（软件层面，硬件不强制，PUSH/POP/CALL/RET 除外）：
R0–R3 传参/临时，R4–R5 保存/地址，R6 = SP，R7 自由。

## 2. 指令格式

所有指令高 5 位为 op1[15:13] + op2[12:11]，剩余 11 位按格式解释：

```
 bit  15 14 13  12 11  10 09 08 07 06 05 04 03 02 01 00
     ┌──────────┬──────┬────────────────────────────────┐
 R   │  010 00  │      │ [rd] │ [rs] │      [fct5]       │  双寄存器运算（rd 兼目的）
 S   │  010 01  │      │ [rd] │ [shamt4] │   [fct4]      │  立即数移位
 I8  │ 001/110  │      │ [rd] │      Immediate[7:0]      │  寄存器 + 8 位立即数
 M   │  011 xx  │      │ [rd] │ [rb] │   Imm5[4:0]       │  访存（基址 + 偏移）
 FM  │ 000 01/1x / 001 10│ [rd] │ [rb] │ Imm5[4:0]       │  远访存（寄存器对拼 22 位物理地址，v3）
 A   │ 100 0x   │      │ [rgs]│  o  o  o  o  o  o  o  o  │  单寄存器（PUSH/POP/JR）
 J11 │ 101 x0   │      │         Immediate[10:0]         │  11 位 PC 相对跳转
 J8  │ 101 01   │      │[flg][cm]│   Immediate[7:0]      │  条件跳转
 C   │ 111 0x   │      │ [rgs]│  [cr4] │  o  o  o  o     │  控制寄存器传送
 Y   │ 111 10   │      │ [fct3]│  o  o  o  o  o  o  o  o │  系统（TRAP/ERET）
 N   │ 000 00 / 111 11 │  x  x  x  x  x  x  x  x  x  x  x │  NOP / HLT
```

字段：`[rd]/[rs]/[rb]/[rgs]` 均为 3 位通用寄存器号（R0–R7）；
`[shamt4]` 移位量；`[flg]` 标志选择（`11:Z 10:V 01:S 00:C`）；`[cm]` 期望标志值；
`[cr4]` 控制寄存器号；`o` 保留位（必须为 0 ❓ 或忽略）。

## 3. 指令编码总表

### 3.1 空操作 / 停机

| 助记符 | 编码 | 语义 |
|---|---|---|
| NOP | `0x0000`（`000 00` + 全 0） | 无操作；空白内存天然是 NOP |
| HLT | `0xFFFF`（`111 11` + 全 1） | 停机 |

### 3.2 立即数装载（I8）

| 助记符 | opcode | 语义 |
|---|---|---|
| MOVI  | `001 00` | `R[rd] = zext(Imm8)`（低字节置数） |
| MOVUI | `001 01` | `R[rd] = Imm8 << 8`（高字节置数） |

装载任意 16 位常量：`MOVUI Rd, hi` + `ORI Rd, lo`（见 3.3）。

### 3.3 立即数运算（I8）

| 助记符 | opcode | 语义 | 立即数扩展 |
|---|---|---|---|
| ADDI | `110 00` | `R[rd] += sext(Imm8)`，置标志 | 符号 |
| ANDI | `110 01` | `R[rd] &= zext(Imm8)`，置标志 | 零 |
| ORI  | `110 10` | `R[rd] \|= zext(Imm8)`，置标志 | 零 |
| CMPI | `110 11` | `R[rd] - zext(Imm8)`，仅置标志不写回 | **零** ⚠ 见注 |

（原版立即数逻辑只能操作 R0，v2 放开到任意寄存器。）

⚠ CMPI 采用**零扩展**（第一阶段实现时裁决）：符号扩展会导致 `CMPI R1, 0xFF`
在 R1=0x00FF 时永远不相等（sext(0xFF)=0xFFFF），与第 5 节样例矛盾。
代价是 CMPI 无法直接与负数常量比较——需要时请 `MOVI` 装载后改用 `CMP`。
与逻辑类立即数（ANDI/ORI）零扩展的规则保持一致。

### 3.4 寄存器运算（R，opcode `010 00`，fct5）✅ 全部可操作 R0–R7

统一语义：`R[rd] = R[rd] OP R[rs]`（rd 兼作目的寄存器），置相应标志。

| fct | 助记符 | 运算 | | fct | 助记符 | 运算 |
|---|---|---|---|---|---|---|
| `00000` | ADD  | 加 | | `01011` | NAND | 与非 |
| `00001` | SUB  | 减 | | `01100` | NOR  | 或非 |
| `00010` | ADC  | 带进位加 | | `01101` | NOT  | `R[rd] = ~R[rs]` |
| `00011` | SBB  | 带借位减 | | `10000` | MOV  | `R[rd] = R[rs]` |
| `00100` | MUL  | 乘法低 16 位 | | `10001` | XCHG | 交换 rd/rs |
| `00101` | MLH  | 乘法高 16 位 | | `10010` | CMP  | 有符号比较，仅置标志 |
| `00110` | DIV  | 除法商 | | `10011` | CMPU | 无符号比较，仅置标志 |
| `00111` | REM  | 除法余数 | | `10100`–`11000` | SHL/SHR/SAR/ROL/ROR | 按 `R[rs][3:0]` 移位 |
| `01000` | AND  | 与 | | 其余 | — | 保留 |
| `01001` | OR   | 或 | | | | |
| `01010` | XOR  | 异或 | | | | |

（原版 MUXL/MUXH/DIVQ/DIVR 更名 MUL/MLH/DIV/REM；CMP/CMPU 不写回。）

**标志规则（第一阶段实现时裁决，仿真已验证）**：

- CMP / CMPU 都做 `rd - rs`：Z/S/C 相同（C = 无借位，即无符号 rd ≥ rs）；
  **CMP 置有符号溢出 V，CMPU 强制 V = 0**。
  软件判断：有符号大小看 `S ⊕ V`，无符号大小看 `C`。
- MOV：置 Z/S，清 C/V；MOVI / MOVUI / MFC / POP / LOD **不动标志**。
- 移位（含 3.5）：C = 最后移出位；Z/S 按结果；V = 0；移位量为 0 时结果与标志均不变。
- MUL / MLH / DIV / REM：Z/S 按结果，C = V = 0。
- ADC / SBB 使用 C 作为进位/借位输入。
- XCHG 在硬件上实现为两拍写回（先 rd ← rs，再 rs ← 原 rd），不占 ALU。

### 3.5 立即数移位（S，opcode `010 01`，fct4）

`R[rd] = R[rd] SHIFT shamt`：

| fct | `0000` | `0001` | `0010` | `0011` | `0100` |
|---|---|---|---|---|---|
| 助记符 | SHL | SHR | SAR | ROL | ROR |

（修正了原版文档移位编码错位的问题；fct 编码连续、无重复。）

### 3.6 访存（M，opcode `011 xx`）✅ 栈并入主内存后通用

地址 = `R[rb] + sext(Imm5)`；基址可以是**包括 R6(SP) 在内的任何寄存器**。

| 助记符 | opcode | 语义 |
|---|---|---|
| LOD.W | `011 00` | `R[rd] = MEM16[addr]`，addr 必须偶数，否则地址未对齐异常 |
| STR.W | `011 01` | `MEM16[addr] = R[rd]`，同上 |
| LOD.B | `011 10` | `R[rd] = zext(MEM8[addr])`，无对齐要求（新增 ✅） |
| STR.B | `011 11` | `MEM8[addr] = R[rd][7:0]`，无对齐要求（新增 ✅） |

### 3.6b 远访存（FM，v3 新增）✅

22 位**物理**地址由固定偶奇寄存器对拼出：对选择看 `rb[2:1]`（rb 的 bit0 保留、忽略），
`rlo = R[{rb[2:1],1'b0}]`、`rhi = R[{rb[2:1],1'b1}]`，即 R1:R0 / R3:R2 / R5:R4 / R7:R6 四对：

```
phys = ( {rhi[5:0], rlo} + sext22(Imm5) ) & 0x3FFFFF    （4MB 物理空间）
```

| 助记符 | opcode | 语义 |
|---|---|---|
| FLOD.W | `000 01` | `R[rd] = MEM16[phys]`，phys 必须偶数，否则地址未对齐异常（excode=3） |
| FSTR.W | `000 10` | `MEM16[phys] = R[rd]`，同上 |
| FLOD.B | `000 11` | `R[rd] = zext(MEM8[phys])`，无对齐要求 |
| FSTR.B | `001 10` | `MEM8[phys] = R[rd][7:0]`，无对齐要求 |

- 远访存**绕过 banking 与 MMIO**，直达物理 RAM —— 供内核/驱动管理任意进程的
  内存或大缓冲区用（banks 切不过来的场景）；用户态要碰外设请回到直通态或用系统调用。
- 不置标志；除对齐检查外行为与对应近访存一致。
- `001 11`、`010 1x`、`100 11` 仍为保留主 opcode（非法指令，excode=4）。

### 3.7 栈（A，硬件隐含使用 R6=SP，栈向下生长）

| 助记符 | opcode | 语义 |
|---|---|---|
| PUSH | `100 00` | `R6 -= 2; MEM16[R6] = R[rgs]` |
| POP  | `100 01` | `R[rgs] = MEM16[R6]; R6 += 2` |
| JR   | `100 10` | `PC = R[rgs]`（计算跳转，配合 MOVI/MOVUI 或 LOD 使用） |

（原版 SPG 栈生长方向配置砍掉，固定向下；独立栈 RAM 砍掉。）

### 3.8 跳转 / 调用 ✅ 全部改为 PC 相对，调用改用栈

| 助记符 | opcode | 格式 | 语义 |
|---|---|---|---|
| J    | `101 00` | J11 | `PC += sext(Imm11)`（范围 ±1024 字节） |
| JCC  | `101 01` | J8  | 若 `flag[flg] XNOR [cm]` 则 `PC += sext(Imm8)`（±128 字节） |
| CALL | `101 10` | J11 | `R6 -= 2; MEM16[R6] = PC+2; PC += sext(Imm11)` |
| RET  | `101 11` | —   | `PC = MEM16[R6]; R6 += 2` |

**与原版的重要区别**：原版 CALL/RET 用 AR 寄存器保存返回地址，无法嵌套调用；
v2 改为把返回地址压栈，**支持任意层数嵌套调用和递归**。偏移均相对本指令地址。

### 3.9 控制寄存器与系统

| 助记符 | 编码 | 语义 |
|---|---|---|
| MFC | `111 00` + rgs + cr4 | `R[rgs] = CR[cr]`（原版未实现的 CR→GPR，v2 补全） |
| MTC | `111 01` + rgs + cr4 | `CR[cr] = R[rgs]` |
| TRAP | `111 10` + fct=`000` | 陷入（excode=2） |
| ERET | `111 10` + fct=`001` | 异常返回：`PC = EPC; EXL = 0` |

## 4. 寄存器

### 4.1 通用寄存器

R0–R7 完全对称，硬件上无任何特殊寄存器（原版 D/A/SP/CBR 分工取消）。
唯一硬件约定：**PUSH/POP/CALL/RET 隐含使用 R6 作栈指针**。

### 4.2 控制寄存器（简化重做，修复读写不对称 bug）

| 编号 | 名称 | 访问 | 位定义 |
|---|---|---|---|
| CR0 | ZERO | R | 恒 0 |
| CR4–CR7 | BANK0–BANK3 | R/W | 各 8 位 bank 号（读 `{8'h00, bank}`，写低 8 位），复位值 = 窗口号 0/1/2/3（直通）；v3，见第 8 节 |
| CR8 | Status | R/W | `IM[7:4]`（4 位中断屏蔽）、`MAPE[3]`（banking 使能，v3）、`EXL[2]`、`IE[1]`、`EM[0]` |
| CR9 | Cause | R（硬件写） | `IP[7:4]`（4 路中断挂起）、`MAPS[3]`（MAPE 影子位，v3）、`excode[2:0]` |
| CR11 | EPC | R（硬件写） | 异常发生时的 PC |
| CR15 | PRID | R | 处理器 ID = `0x0403`（type=0x10，version=3） |
| 其余 | — | — | 保留，读出为 0，写忽略 |

Status 读写位布局**完全一致**（原版写侧 IM 错位到 bits12:9 的 bug 已修）。

### 4.3 异常模型（简化）

- 异常源与 excode：`1`=外部中断、`2`=TRAP、
  `3`=地址未对齐、`4`=非法指令（未分配主 opcode；已分配指令的保留位/保留 fct 不查，按 NOP 通过）
- 响应：`EPC ← PC`、`excode ← 异常码`、`EXL ← 1`、`MAPS ← MAPE`、`MAPE ← 0`、`PC ← 0xFF00`
  （原版按 excode 索引向量表，v2 简化为**单一入口 0xFF00**，由软件读 Cause 分发；
  v3 起 MAPE 落影子位并切直通 —— 向量页与 MMIO 恒可达，异常进入即"陷入内核态"）
- 返回：ERET 恢复 `PC ← EPC`、`EXL ← 0`、`MAPE ← MAPS`（随 EXL 一同回到映射态）
- 溢出（V）不触发异常，仅置标志（原版 flg 触发中断的机制砍掉）

**精确语义（第二阶段实现时裁决，仿真已验证）**：

- **EPC 指向因异常类型而异**：
  TRAP → `EPC = PC + 2`（跳语义，ERET 后继续执行，否则 EPC 指自身会死循环）；
  未对齐/非法指令 → `EPC = 本指令`（重试语义，handler 修正后 ERET 重新执行）；
  中断 → `EPC = 下一条指令`（FETCH 边界采样，天然精确）。
- **中断判定**：`IE=1 且 EXL=0 且 (irq & ~IM) != 0` 时触发，即 **IM 位 = 1 屏蔽、0 放行**；
  电平敏感、无挂起锁存。`Cause.IP` 锁存进入瞬间的**原始** irq 值（未与 IM 相与），便于调试。
- **EXL 只挡中断不挡故障**：handler 内再发生异常会覆盖 EPC/Cause，软件自行避免。
- 非法指令不可经 ERET 恢复（EPC 指自身且 EPC 软件只读）：handler 需自行修改返回路径
  （如 MTC 清 EXL 后 JR 到恢复点）。
- 异常入口占一个 EXC 气泡拍（多周期 FSM），寄存器锁存在进入该拍的时钟沿完成。

## 5. 样例程序（计数循环，对应原版样例）

```
 地址      机器码     汇编
0x0000:   20 FF      MOVI R0, 0xFF
0x0002:   22 01      MOVI R2, 1
0x0004:   41 40      loop: ADD R1, R2        ; 010 00 | 001 | 010 | 00000
0x0006:   D9 FF      CMPI R1, 0xFF           ; 110 11 | 001 | 11111111
0x0008:   AE FC      JCC  Z=0, loop          ; 101 01 | 11 | 0 | 11111100 (offset=-4)
0x000A:   FF FF      HLT
```

注：表中机器码按**字**书写（如字 `0x20FF`）；存入内存时遵循小端，
即 `mem[0]=0xFF, mem[1]=0x20`。第一条指令 MOVI/MOVUI/CMPI/JCC 均不依赖
标志初值，复位后标志状态随意。HLT 停机时 PC 停留在 HLT 指令自身地址
（0x000A），不再推进。

```
; 嵌套调用演示（v2 新能力）
0x0010:   B0 03      CALL func        ; 101 10 | offset=+3... （示意）
0x0012:   ...
func:     80 00      PUSH R0          ; 100 00 | 000 | ...
          ...                        
          88 00      POP R0           ; 100 01 | 000 | ...
          B8 00      RET              ; 101 11 | ...
```

## 6. 与原版的差异决策记录

| # | 决策 | 原版 | v2 | 理由 |
|---|---|---|---|---|
| 1 | ALU 寄存器范围 | 仅 R0–R3 | R0–R7 | 2 位字段是当年妥协，3 位字段编码空间够用 |
| 2 | 栈 | 独立 12 位栈 RAM | 主内存，R6=SP | 与真实 CPU 一致；支持栈上分配 |
| 3 | CALL/RET | AR 寄存器，不可嵌套 | 返回地址压栈 | 支持嵌套/递归调用 |
| 4 | 跳转 | 段内绝对 + 相对混合 | 全部 PC 相对 | 位置无关代码，译码/数据通路统一 |
| 5 | 字节访存 | 无（字访问+对齐异常） | LOD.B/STR.B | 处理字符串/字节数据的刚需 |
| 6 | 移位编码 | 文档错位、有重复 | 连续无重复（3.5） | 修文档笔误 |
| 7 | CR⇄GPR | 半成品（读通路悬空） | MFC/MTC 双向 | 补全 |
| 8 | Status | 读写不对称、en/ERL 死位 | 读写对称、删死位 | 修 bug |
| 9 | 异常向量 | 按 excode 索引表 | 单一 0xFF00 | 简化，软件分发 |
| 10 | 大小端 | 可配置 BLE | 固定小端 | 简化 |
| 11 | flg 触发中断 | 支持 | 砍 | 溢出用标志位查询即可 |
| 12 | `[i]` 位、IV/VI-II 等 | 未接线/未使用 | 砍 | 不保留画饼 |
| 13 | 物理寻址（v3） | 64KB 线性 | banking（CR4–CR7+MAPE）+ 寄存器对远访存 | 4MB 物理空间；见第 8 节、3.6b |
| 14 | PRID（v3） | 0x0402 | 0x0403 | version=3 |

## 7. 设计决策记录（原"待议项"）

1. ✅ **R6(SP) 复位值 = 0xFFFE（固定）**。参考：Cortex-M 复位时从向量表加载 SP、
   8051 固定 SP=0x07（硬件初值流派）；RISC-V/MIPS/ARM-A 则留给 boot 代码。
   v2 取简化 Cortex-M 方案：固定复位到 64K 空间栈顶，程序上来即可 PUSH；
   RAM 配置变化时由启动代码用 `MOVUI`+`ORI` 重设。
2. ✅ **保留位 `o` 直接忽略**，译码器不做严格检查（译码简单）。
3. ✅ **Imm5 偏移 ±16 字节够用**，大栈帧靠 `ADDI R6, -N` 配合。
4. ✅ **除零采用 RISC-V 规则**：`DIV` 除零 → 商 = `0xFFFF`；`REM` 除零 → 余数 = 被除数。
   不触发异常，行为完全确定。（对比：x86 硬件异常；MIPS 未定义；ARM 默认返回零。）
5. ✅ **JCC ±128 字节可接受**，远跳转用 J/JR 接力。
   另：v2 初版为多周期实现（无流水线），**无延迟槽**。
6. ✅ **v3 内存扩展裁决**（仿真已验证，tb_memmap）：
   - 远访存地址对固定为偶奇寄存器对（rb 的 bit0 忽略），高位寄存器仅低 6 位参与拼接；
   - MAPE 兼作特权位：映射态下 MMIO/向量页一律不可达，异常进入 = 陷入内核态；
     备忘版"窗口 0 锁定"取消；
   - 远访存绕过 banking 与 MMIO；远字访存奇物理地址同样触发 excode=3。

## 8. 内存 banking（4MB 物理寻址）✅（v3 转正，语义较备忘版有修订）

> 动机：64KB 逻辑空间不足以支撑"每进程独立地址空间"的 OS 玩法
> （参照系：UNIX V5/V6 与 Mini-UNIX 跑在 56KB 级内存的 PDP-11 上；
> Xv6 绑死 32/64 位线性地址，移植不现实，目标是 V6 风格玩具内核）。
> 与 3.6b 远访存叠加：banking 给进程隔离，远访存给内核/驱动连续大空间。

### 8.1 方案：银行切换（bank switching，Z80/6502 时代经典做法）

- 64KB 逻辑空间按 `addr[15:14]` 切 **4 个 16KB 窗口**；
- 每窗口一个 8 位 bank 寄存器（CR4–CR7 = BANK0–BANK3），
  物理地址 = `{bank[w], addr[13:0]}` = **22 位 = 4MB**；
- 不选 8086 段式（段重叠/far pointer 噩梦）和 PDP-11 全功能 MMU（硬件过重）。

### 8.2 编程接口（全部用现成机制，无新指令）

| 机制 | 位置 | 说明 |
|---|---|---|
| BANK0–BANK3（8 位 bank 号） | **CR4–CR7** | 经 MFC/MTC 访问，复位值 = 窗口号（直通） |
| MAPE（映射使能） | **Status bit3** | 0 = 直通映射（`phys = {6'h00, addr}`，二进制兼容 v2），1 = banking 生效 |
| MAPS（MAPE 影子位） | **Cause bit3**，只读 | 异常进入时保存 MAPE |
| 异常联动 | 硬件行为 | 进入异常：`MAPS ← MAPE、MAPE ← 0`；ERET：`MAPE ← MAPS`（随 EXL 一同恢复） |

### 8.3 MAPE 兼作特权位（v3 裁决，替代备忘版的"窗口 0 锁定"）

- MAPE=1 时**整个 64KB 逻辑空间**（含 `0xF000`–`0xFEFF` 的 MMIO 窗口和
  `0xFF00` 向量页）全部经 bank 重映射到物理 RAM —— **MMIO 仅在 MAPE=0
  直通态可达**，向量 fetch 亦然。
- 推论：异常进入硬件自动 `MAPE ← 0` 等价于陷入内核态（handler 直通运行，
  向量恒可达、可碰 MMIO）；ERET 恢复 MAPE 即回用户态。
  用户进程无法触碰外设与其他 bank，I/O 走 TRAP 系统调用。
- 因此备忘版的"窗口 0 锁定恒映射 bank 0"**取消**（内核不在映射态运行，
  无需常驻窗口；CR4 可正常读写，只是内核自己不用）。
- 翻译在核内完成：内核向总线输出 22 位物理地址 + `mape` 电平，
  总线仅在 `mape=0` 且非远访存时译码 MMIO（防 bank 号 = 0 时物理地址
  巧合落入 0xF000 窗口被误判为 MMIO）。
- 远访存（3.6b）永远绕过 banking 与 MMIO，是内核管理任意物理内存的手段。

### 8.4 实施与后续路线

1. ✅ 第二阶段：访存/栈/CALL/RET
2. ✅ 总线化 + MMIO 地址译码
3. ✅ **本扩展**（CR4–CR7 + MAPE/MAPS + 核内地址拼接；远访存见 3.6b）
4. 定时器中断（OS 调度）、MMIO 块设备（文件系统）——玩具内核的其余前置
5. ⚠ 仿真内 4MB 无成本；FPGA 上 4MB 需外挂 SRAM/SDRAM 控制器，是独立工程

## 9. 内存映射与 MMIO（第三阶段实现）✅

> 总线化：`rtl/bus.v` 在内核与内存/外设之间做地址译码路由；
> v3 起内核输出 22 位物理地址 + `mem_far` + `mape_o`（banking 翻译在核内，
> 见第 8 节）；第一个外设是 UART（`rtl/uart.v`）。

### 9.1 地址映射（MAPE=0 直通态；MAPE=1 时整个 64KB 均为 banked RAM，MMIO 不可达）

| 地址范围 | 归属 | 说明 |
|---|---|---|
| `0x0000`–`0xEFFF` | RAM（56KB） | 程序与数据 |
| `0xF000`–`0xFEFF` | MMIO 外设区（4KB） | 每设备 16 字节，槽 i 基址 = `0xF000 + i*0x10`（i=0..7 可用） |
| `0xFF00`–`0xFFFF` | RAM 保留页（256B） | **异常向量 0xFF00 必须留在 RAM** ✅ |

- 槽 0（`0xF000`）= UART；槽 1–7（`0xF010`–`0xF070`）预留。
- MMIO 空洞（`0xF080`–`0xFEFF` 及未接设备的槽）：**读返回 0、写忽略，不触发异常** ✅。
- 对齐规则与 RAM 一致：字访问奇地址 → 地址未对齐异常（excode=3），
  判定在内核（与访存通路共用），总线与设备不重复检查 ✅。
- 字节访问语义与 RAM 相同：字节读按小端取寄存器字的高/低字节（zext），
  字节写偶地址等效写寄存器低字节。

### 9.2 UART（槽 0，简化 16550 风格，16 位字寄存器）

| 偏移 | 名称 | 访问 | 位定义 |
|---|---|---|---|
| `0x0` | RXDATA | R | 低 8 位 = 接收字节；**读后 rx_ready 清 0**（弹出） |
| `0x2` | TXDATA | W | 低 8 位写入即发送 |
| `0x4` | STATUS | R | bit0 `rx_ready`、bit1 `tx_ready`（恒 1） |
| `0x6` | CONTROL | R/W | bit0 接收中断使能 `ie` |

- 中断：`irq = rx_ready & ie`，接内核 `irq[0]`；
  读 RXDATA 清除 rx_ready 后中断线自动撤除（电平型，无需软件确认）✅。
- ⚠ 仿真模型无真实波特率时序：TX 写入立即完成（tx_ready 恒 1），
  RX 由 testbench 预载/注入接收 FIFO。上 FPGA 需另加波特率发生器与移位器，
  寄存器布局保持不变。
